# Security Policy

Thank you for helping keep QSMPDLE and its players safe.

QSMPDLE is an independent, fan-made web game maintained as a personal project. Security vulnerabilities are taken seriously, and responsible disclosure is appreciated.

## Supported Versions

Security fixes are applied to the latest maintained version of QSMPDLE.

## Supported Versions

Use this section to tell people about which versions of your project are
currently being supported with security updates.

The following are covered:

- The production website at https://qsmpdle.com.
- The currently maintained application source code.

Older deployments, abandoned versions, and third-party forks are not officially supported.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues or social media.**

Instead, use GitHub's private vulnerability reporting feature:

1. Open the repository's **Security** tab.
2. Navigate to **Advisories**.
   3. Select **Report a vulnerability**.

Please include:

- A description of the vulnerability and its potential impact.
- The affected component, endpoint, or functionality.
- Steps to reproduce the issue.
- A proof of concept, if available.
- Any suggested mitigations or fixes.

Do not include exposed credentials or unredacted personal information in your report.

## Scope

Examples of security vulnerabilities include:

- Cross-site scripting (XSS), injection attacks, and similar vulnerabilities.
- Unauthorized access to application data or infrastructure.
- Exposure of credentials, secrets, or sensitive information.
- Vulnerabilities that allow unintended modification of stored data.
- Security misconfigurations with demonstrable impact.

Gameplay bugs, inaccurate character information, incorrect guesses, and visual defects should be reported through regular GitHub issues unless they have a security impact.

## Responsible Disclosure

When investigating a potential vulnerability, please:

- Avoid accessing, modifying, or deleting other users' data.
- Avoid disruptive testing, denial-of-service attacks, or excessive automated requests.
- Do not attempt social engineering or attacks against third-party services.
- Allow reasonable time for the vulnerability to be investigated and addressed before public disclosure.

## Response and Resolution

Reports are reviewed on a best-effort basis.

Confirmed vulnerabilities will be prioritized according to their severity, exploitability, and potential impact. Fixes will be deployed as appropriate, with public disclosure coordinated when necessary.

As an independently maintained project, QSMPDLE cannot guarantee specific response or resolution times.

## Bug Bounty

QSMPDLE does not currently operate a paid bug bounty program. Security research and responsible reports are appreciated, but monetary compensation is not offered.
